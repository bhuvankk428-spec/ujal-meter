URJA METER OPS API - 5 MINUTE DEMO SCRIPT
=========================================

Target runtime: 4:50 to 4:58
Hard stop: 5:00
Pace: about 145-155 words per minute
Record at 1080p, 30 fps, with a clear cursor and readable terminal font (16-18 pt).

This file has four parts:
1. What to prepare before recording
2. Screen layout and run of show
3. Exact narration and screen actions
4. Failure fallbacks and claims to avoid


1. BEFORE RECORDING
-------------------

Start both processes from D:\flork using HOW_TO_RUN.md:

  Terminal 1:
  .\.venv\Scripts\python.exe -m uvicorn mock_portal.app:app --host 127.0.0.1 --port 9000

  Terminal 2:
  .\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000

Then do this preparation:

- Open http://127.0.0.1:8000/ and wait until the status pill says "Portal ready".
- Click the Fleet, Hierarchy, and Health tabs once so the pages are warm.
- Return to the Fleet tab.
- Do NOT open meter MTR-0009. It will be used for the re-auth demo.
- Open http://127.0.0.1:8000/docs in a second browser tab.
- Keep a terminal window open at D:\flork, with large text and a short prompt.
- Keep a second terminal tab ready for pytest.
- Turn off notifications, browser extensions, and any personal tabs.
- Close the browser DevTools panel.
- Hide the mouse until you need it.
- Do one 20-second test recording to check audio level and text size.

Recommended browser tabs, left to right:
  1. Dashboard: http://127.0.0.1:8000/
  2. API docs: http://127.0.0.1:8000/docs
  3. Terminal: D:\flork

Useful terminal commands, already tested:

  curl.exe -s -i http://127.0.0.1:8000/api/v1/meters/MTR-9999

  curl.exe -s -X POST http://127.0.0.1:9000/_control/expire

  curl.exe -s -o NUL -w "HTTP %{http_code}\n" http://127.0.0.1:8000/api/v1/meters/MTR-0009

  curl.exe -s http://127.0.0.1:9000/_control/stats

  .\.venv\Scripts\python.exe -m pytest -q

Important: keep the real portal limitation visible in the video. The mock is a
deliberate test double, not a claim that the real portal was accessed.

[0:52-1:22] ARCHITECTURE

SCREEN: Show the architecture diagram in README.md (or the project tree). If
using an editor, zoom so the app/ and portal/ boundaries are readable.

SAY:
"Under the hood, this is an anti-corruption layer. FastAPI handles validation,
pagination, and RFC 9457 problem+json errors. The service layer owns the
bulk-first meter snapshot, the hierarchy builder, and a stale-while-revalidate
cache. The portal layer owns one shared session, expiry detection, bounded
retries, a concurrency limit, and a circuit breaker. Parsers turn HTML, CSV, and
JSON into untouched strings. Normalizers are the only path to a public model.
Anything lossy becomes a quality flag, not a silent repair."

4. FAILURE FALLBACKS AND CLAIMS TO AVOID
----------------------------------------

IF THE DASHBOARD DOES NOT LOAD:
- Check http://127.0.0.1:9000/health first, then http://127.0.0.1:8000/ready.
- If needed, use docs/fleet.png as a still image and keep narrating. Do not
  spend video time debugging.

IF THE RE-AUTH DEMO DOES NOT SHOW A NEW LOGIN:
- MTR-0009 may already be cached. Restart the API, warm only the dashboard, and
  use MTR-0009 again. Do not switch to a meter you already opened.
- If the mock control endpoint is disabled, skip the live proof and say:
  "The integration test covers this with ten concurrent requests and exactly
  one login." Do not pretend the live demo ran.

IF TESTS FAIL:
- Do not hide it. Say: "The last verified run was seventy-seven passing and one
  skipped. I won't claim a green run I did not see." Use a saved terminal
  screenshot only if it is clearly labeled as the earlier verified run.

DO SAY:
- "The real portal was not available; this is a mock-backed adapter."
- "Read-only: GET plus the internal login POST."
- "One shared operator session; single-process cache."
- "Quality flags instead of silent repairs."
- "The committed OpenAPI schema is checked for drift in CI."

DO NOT SAY:
- "This is connected to the real Urja portal."
- "This is production-ready."
- "Zero defects" or "all data is clean."
- "It scales horizontally"; the cache and session are intentionally
  single-process.
- "The Docker build was verified here"; it was not, because no Docker engine
  was available in this environment.
